Descripción General del Sistema

Plataforma de base de conocimiento autoalojada, de código abierto, construida con PHP y Laravel.

Organización jerárquica

El contenido se organiza en Libros, Capítulos y Páginas, facilitando la gestión de documentación técnica a cualquier escala.

Control de acceso por roles

Sistema de control de acceso basado en roles con niveles de administrador, editor y visualizador. Permisos aplicables a nivel de libro, capítulo y página.

Búsqueda avanzada

Indexación de contenido completa con soporte para búsqueda de texto libre, filtros por tipo y etiquetas personalizadas.

Edición enriquecida y Markdown

Dos modos de edición disponibles: editor visual enriquecido y editor Markdown, con soporte para diagramas, código con resaltado y tablas.

Exportación múltiple

Las páginas se pueden exportar en formatos PDF, HTML, texto plano y Markdown, facilitando la portabilidad del contenido.

API REST y Webhooks

Interfaz de programación de aplicaciones REST para integración con sistemas externos. Soporte para webhooks, LDAP, SAML y autenticación OAuth2.

Estrategia de Pruebas

Proceso progresivo de evaluación técnica planificado a lo largo de los cuatro sprints del proyecto.

Pruebas Unitarias

Cobertura de 91.44% en líneas sobre la suite completa, conformada por 1,802 pruebas. Incluye 45 pruebas propias del equipo sobre los servicios principales: SlugGenerator, SearchService, PageService, BookService y ChapterService.

Completado: Sprints 1 y 2

Pruebas Funcionales

Desarrollo de 30 casos de prueba de caja negra fundamentados en técnicas de Partición de Equivalencia, Valores Límite, Tabla de Decisión y Transición de Estados. Ejecución manual en entorno de calidad.

Completado: Sprint 2

Pruebas de Integración

Planificación de 8 puntos de integración y 6 casos detallados. La ejecución práctica se realizará durante el tercer hito, en conformidad con los requerimientos académicos.

Planificado para Sprint 3

Documentación Técnica

Registros formales y detallados del proceso de pruebas, almacenados en el repositorio del proyecto.

  • Especificación de Requisitos del Sistema
    Definición de requisitos funcionales y no funcionales, acompañados de su respectiva matriz de trazabilidad.
  • Plan de Pruebas Unitarias
    Identificación de componentes del repositorio, técnicas de diseño a aplicar, criterios de aceptación y cronograma establecido.
  • Reporte de Pruebas Unitarias y Cobertura
    Resultados de la ejecución, análisis de métricas de cobertura, aportes individuales y registro de hallazgos técnicos.
  • Diseño de Casos de Pruebas Funcionales
    Detalle de los 30 casos de prueba de caja negra correspondientes a los requisitos funcionales identificados.
  • Plan de Pruebas de Integración
    Definición de 8 puntos de integración y estrategia de implementación. Programado para ejecución en el Hito 3.
  • Evidencias de Integración Continua
    Documentación sobre la configuración del flujo de trabajo automatizado para la validación de pruebas unitarias.
